# Corporate Knowledge Assistant: ответы по PDF и Wiki со ссылками на страницы

Корпоративный ассистент отвечает на вопросы сотрудников по внутренней базе знаний
(PDF-инструкции и Wiki) и подтверждает каждый факт ссылкой **[Файл.pdf, стр. X]** или
**[Название Wiki-статьи]**. Каждая ссылка проверяется автоматически: существует ли
файл и страница и действительно ли на этой странице написан этот факт.

Домашнее задание курса LLM.

* **Отчёт:** [`notebooks/report.ipynb`](notebooks/report.ipynb). Все выводы сохранены,
  ноутбук читается без запуска.
* **Лог тестов (5+ запросов с полными ответами и ссылками):** [`docs/test_log.md`](docs/test_log.md)
* **Проверяющему:** карта «требование → что сделано → где смотреть» в [`ДЛЯ_ПРОВЕРЯЮЩЕГО.md`](ДЛЯ_ПРОВЕРЯЮЩЕГО.md)

## Главное

| что проверялось | строгий промпт | базовый промпт (3 правила задания) |
| --- | --- | --- |
| ссылки на выдуманные файлы, страницы, статьи | **0 из 38** | 0 из 8 |
| провокации вне базы → «Я не знаю» без ссылок | **3/3** | 3/3 |
| прямые вопросы: факт + верная страница | **5/5** | 3/5 |
| факты, подтверждённые ссылкой на страницу, где они реально написаны | **23/32** | 9/32 |
| агрегация из 2+ источников | 1/4 | 1/4 |

1. **Галлюцинаций источников нет вообще**, даже с базовым промптом. Дело не столько в
   запретах, сколько в формате: в заголовке каждого блока контекста лежит готовая ссылка,
   модели остаётся её скопировать. Остающиеся ошибки другого рода — ссылка валидна по
   форме, но факт подтверждает не она, или вторая ссылка молча пропущена.
2. **Номер страницы ломается при парсинге и нарезке, а не в модели.** В PDF три
   нумерации: физическая, печатная («— 2 —» в колонтитуле и номера в оглавлении) и
   PageLabels. Без номера страницы в метаданных модель берёт печатный и ошибается ровно
   на 2 (титул и оглавление) в **4 из 5** вопросов «на какой странице…». С метаданными —
   **15 из 15** верно, даже когда оглавление попадает в контекст.
3. **chunk_size влияет на точность страницы только при сквозной нарезке.** Если резать
   документ целиком, чанк получает страницу своего начала. Точность номера падает
   **со 100% до 78%** на чанках 2500 символов: 81% из них захватывают две страницы.
   При нарезке внутри страницы — 100% при любом размере.
4. **В длинном ответе модель теряет не источник, а гранулярность.** Каждый смысловой блок
   подписан (16/16), но в длинных списках ссылку получают лишь **59%** пунктов: одна
   ссылка на блок. Просьба писать абзацами возвращает 100%. Сборка ответа из подответов
   даёт больше фактов (11/14 против 8/14), зато в 3 случаях модель выносит источники в
   строку «Ссылки: […]» в конце.
5. **Агрегация — главное слабое место (1/4).** Модель сливает два факта в одно
   предложение со ссылкой на один источник и молча выбирает один из двух
   противоречащих документов (в корпусе есть два архивных документа 2024 года с
   разными правилами удалёнки и два разных списка разрешённого ПО).

## Как устроено

```
data/source_md (36 md, корпус урока)
   │  tools/build_corpus.py — reportlab: титул, оглавление, колонтитулы, PageLabels
   ▼
data/pdf (4 PDF, 33 стр.) + data/wiki (4 HTML)
   │  src/parsing.py — PyMuPDF get_text("dict"): шрифты → заголовки, координаты → без колонтитулов,
   │                   пропуск титула/оглавления; BeautifulSoup: только <article>
   ▼
Segment {source, page, page_label, chapter, header, text}
   │  src/chunking.py — RecursiveCharacterTextSplitter 400/80, чанк не пересекает страницу
   ▼
ChromaDB (multilingual-e5-base) ── метаданные хранятся с каждым вектором
   │  src/index.py retrieve() — top-5 с метаданными
   ▼
«Контекст 1 (Источник: X.pdf, стр. 4; раздел «…»; ссылка: [X.pdf, стр. 4]): текст»
   │  src/prompts.py — строгий системный промпт
   ▼
YandexGPT 5 Lite ─→ ответ ─→ src/citations.py: статус каждой ссылки + сверка факта с текстом страницы
```

| Компонент | Выбор |
| --- | --- |
| Парсинг | PyMuPDF (PDF), BeautifulSoup + lxml (HTML) |
| Эмбеддинги | `intfloat/multilingual-e5-base`, локально |
| Векторная база | ChromaDB (персистентная, `data/chroma`) |
| LLM | YandexGPT 5 Lite, temperature 0.1, OpenAI-совместимый API Yandex AI Studio |
| Стоимость всех экспериментов | 113 вызовов, 121 тыс. токенов, ≈ 24 ₽ |

## Запуск

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Ключ не обязателен: без него ответы берутся из `outputs/llm_cache` (режим `replay`).
Для новых вопросов скопируйте `.env.example` в `.env` и впишите `YC_API_KEY` и `YC_FOLDER_ID`.

```bash
.venv/bin/python -m tools.build_corpus
```

```bash
.venv/bin/python -m src.index
```

```bash
.venv/bin/python -m src.rag "Какая минимальная длина пароля?"
```

Эксперименты и отчёт:

```bash
.venv/bin/python -m src.experiments retrieval
```

(также `main`, `long`, `pages`, `chunks_llm`; ответы модели кэшируются, повторный прогон бесплатен)

```bash
.venv/bin/python -m tools.build_notebook && .venv/bin/python -m tools.build_test_log
```

```bash
LLM_MODE=replay .venv/bin/jupyter nbconvert --to notebook --execute --inplace notebooks/report.ipynb
```

## Структура

```
src/config.py        пути, состав сборников, параметры поиска и модели
src/parsing.py       PDF (PyMuPDF) и HTML (BeautifulSoup) → сегменты с метаданными
src/chunking.py      нарезка: page (в пределах страницы) / flow / naive
src/index.py         эмбеддинги, ChromaDB, retriever
src/prompts.py       системные промпты, формат контекста с источниками
src/llm.py           YandexGPT + дисковый кэш ответов
src/rag.py           цепочка вопрос → поиск → ответ; декомпозиция многотемных вопросов
src/citations.py     разбор и проверка ссылок, покрытие ответа ссылками, кликабельные ссылки
src/eval_set.py      27 проб для ретривера, 15 вопросов, 5 вопросов «на какой странице»
src/experiments.py   все эксперименты → outputs/*.json
tools/               сборка корпуса, ноутбука и лога тестов
```
